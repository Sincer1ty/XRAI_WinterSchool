# 안경 음성·STT 진단 사용 방법

이 문서는 새로 추가한 진단 화면의 사용 방법이다. 빌드·테스트 실행과 통과 판정은 사용자가 한다. 최신 실행 기록은 [2026-11-21 빌드·테스트 기록](diagnostics-results-2026-11-21.md)을 참고한다. 실기기 기능의 최종 판정은 사용자 확인 필요다.

## 1. 수정한 프로젝트 열기

1. Android Studio의 SDK 설정 창이 열려 있으면 설정을 마치고 프로젝트 화면으로 돌아간다.
2. File → Open에서 이 저장소의 android 폴더를 연다. CXRLSample 원본 사본과 구분한다.
3. Gradle 동기화가 끝나는지 확인한다.
4. 휴대폰을 USB로 연결하고 디버깅을 허용한다.
5. 실행 대상을 휴대폰으로 선택한 뒤 Run을 누른다.

Windows 한글 경로 검사 오류가 나면 기존 setup-windows.md 안내에 따라 영문 경로의 작업 사본에서 실행한다. 그 사본에도 이번 변경 파일이 포함돼 있어야 한다. 빌드 오류는 그대로 공유하며 임의로 SDK 버전을 바꾸지 않는다.

## 2. 진단 화면 열기

1. Hi Rokid 또는 Rokid AI에서 안경 연결을 확인한다.
2. 앱에서 연결 승인을 마친다.
3. 안경 화면 모드 → 안경 화면 열기를 누른다.
4. 새 버튼인 '안경 음성·STT 진단'을 누른다.

버튼이 비활성화돼 있으면 안경 서비스·블루투스·화면 열림 상태를 먼저 확인한다. 안경 앱 모드는 이번 진단 화면의 대상이 아니다.

## 3. 안경 음성 수신 확인

1. '안경 음성 수신 시작'을 누른다.
2. 안경을 착용하고 '오늘은 발표 보조 안경을 소개합니다'라고 말한다.
3. 수신 청크·바이트가 증가하는지, 마지막 수신 후 시간이 갱신되는지 확인한다.
4. 말할 때와 조용할 때 신호 크기(RMS)가 달라지는지 확인한다.

- 바이트 증가: SDK에서 오디오 데이터가 들어온 증거다. 말이 올바르게 담겼다는 판정과는 구분한다.
- 수신 없음: SDK·안경 마이크 권한·연결·코덱을 확인한다. 침묵으로 판정하지 않는다.
- 형식: 기존 샘플과 같은 16 kHz·모노·16비트 PCM으로 가정한다. 실제 형식은 별도 확인이 필요하다.
- 이 진단 화면은 음성을 파일로 저장하지 않는다. 음질을 들어보려면 기존 음성 수신 화면의 녹음·재생 기능을 별도로 사용한다.

## 4. STT 확인

1. 수신 바이트가 증가하는 상태에서 '안경 PCM으로 STT 시작'을 누른다.
2. 요청되면 휴대폰 마이크 권한을 허용한다. STT API 사용에 필요한 권한이며 입력 출처를 증명하지 않는다.
3. 새로운 문장을 말하고 중간·확정 결과와 인식기 입력 파이프 바이트를 확인한다.
4. 끝나면 'STT 입력 종료 · 결과 받기'를 누른다.
5. 강제로 중지하려면 'STT 취소'를 누른다.

- 기본 선택은 기기 내 인식기다. 미지원 또는 한국어 모델 오류가 나오면 코드·메시지를 기록한다.
- 필요하면 STT를 멈춘 뒤 '기기 내 인식기 사용' 스위치를 꺼 기본 인식기를 직접 선택한다. 기본 서비스는 오디오를 외부 서버로 전송할 수 있다.
- 외부 PCM 입력 시험은 Android 13/API 33 이상에서 실행한다. 그 이전 버전은 수신·표시 확인만 가능하다.
- 인식기가 한 문장 후 종료하면 그대로 표시한다. 자동 재시작으로 지속 인식 문제를 숨기지 않는다.
- 입력 종료 후 10초 대기는 진단의 세션 정리 제한이며 제품의 멈춤·힌트 정책이 아니다.
- 음성 입력이 밀리거나 파이프 쓰기가 실패하면 STT를 중지하고 오류를 표시한다.

### 입력 출처를 구분하는 대조 시험

Android 인식기가 외부 오디오를 무시하고 폰 마이크를 사용할 수 있다. 텍스트가 나왔다는 이유만으로 안경 STT 연동 성공이라고 판정하지 않는다.

- 블루투스 연결이 유지되는 범위에서 폰과 안경을 떨어뜨린다.
- 안경 착용자는 문장 A, 폰 근처의 다른 사람은 서로 구분되는 문장 B를 말한다.
- 두 소리가 상대 마이크에도 들어갈 수 있으므로 위치·음량을 조정하며 반복한다.
- 결과가 A/B 중 무엇을 따라가는지 기록한다. 구분되지 않으면 입력 경로는 미확인으로 남긴다.
- 파이프 바이트 증가도 실제 인식 출처의 단독 증거로 사용하지 않는다.

## 5. 힌트 숨김 중 음성 유지 확인

1. 음성 수신과 STT를 시작한다.
2. '시험 문구 표시'를 눌러 안경에 문구가 보이는지 확인한다.
3. '힌트만 숨김 · 음성 유지'를 누른다.
4. 안경에서 문구·아이콘이 실제로 사라지는지 확인한다.
5. '숨김 요청 후 수신' 바이트가 증가하는지 확인하며 새로운 문장을 말한다.
6. 숨김 이후의 새 문장이 STT에 나타나는지 확인한다.
7. 다시 문구를 표시할 수 있는지 확인한다.

숨김은 기존 화면 닫기를 호출하지 않고 텍스트를 비우고 아이콘 크기를 0으로 갱신한다. SDK가 변경을 적용하는지 직접 확인해야 한다. 요청 전송과 실제 화면 반영을 구분한다.

## 6. 회전·재연결·종료 확인

- 진단 화면에서 폰을 회전한다. 진단 ViewModel과 수신량이 유지되는지 확인한다.
- 블루투스를 끊으면 수신이 중지되고 연결 오류가 안내되는지 확인한다.
- 다시 연결한 뒤 '안경 음성 수신 시작'으로 재개한다. 화면이 닫혔다면 진단을 나가서 안경 화면을 다시 연다.
- 진단 화면을 나가거나 앱을 백그라운드로 보내면 수신·STT가 중지된다.
- 회전 시 세션 재생성 문제를 기존 세션 화면 전체에서 수정한 것은 아니다. 이번 별도 진단 Activity는 기존 연결을 재사용한다.

## 8. 추가한 단위 테스트

Pcm16ProbeTest는 잘못된 SDK 범위 거부, 오프셋 적용, 콜백 사이에 나뉜 PCM 샘플, 무음과 입력 없음 구분, 숨김 후 수신량 기준을 확인한다. 실기기 연동을 대신하지 않는다.

사용자가 android 폴더에서 실행할 명령:

~~~powershell
.\gradlew.bat --console=plain testDebugUnitTest --tests "com.rokid.renewcxrlsample.diagnostics.Pcm16ProbeTest"
~~~

예상 결과는 5개 진단 테스트의 성공이다. 2026-11-21 사용자의 실행 요청으로 빌드와 전체 로컬 단위 테스트를 수행했으며, 진단 5개와 기존 1개에서 실패·오류 0개를 확인했다. 자세한 범위와 남은 실기기 확인은 실행 기록을 참고한다.
